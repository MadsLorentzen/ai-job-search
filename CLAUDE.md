## Workflow for New Job Applications
1. User provides a job posting (URL or text)
2. **Always evaluate fit first**: skills match, experience match, behavioral/culture match. Present this assessment to the user before proceeding.
3. If good fit: create targeted CV (`cv/main_<company>.tex`) and cover letter (`cover_letters/cover_<company>_<role>.tex`)
4. **Verify both documents** (see Verification Checklist below)
5. Submit the application (or auto-apply)
6. **Capture the submission record** (see "Submission Record" below) — MANDATORY at submit time
7. Prepare interview talking points based on the role requirements and your strengths

## Submission Record (MANDATORY at submit time)
Every application — cold auto-apply or referral — must produce a complete, reproducible record of **exactly what was submitted**, written at the moment of submission (never reconstructed later, because verbatim free-text is unrecoverable once context is lost).

For each application, create `documents/applications/<company-role-slug>/` containing:
- **`submission.json`** — machine-readable source of truth. Required keys: `company`, `role`, `date_submitted`, `ats_host`, `fit_rating`, `channel`, `materials` (cv + cover paths), `contact_and_standard_fields` (every contact/standard field value entered), `location_entered`, `salary_entered`, `source_answer`, `free_text_answers` (array of `{q, a}` with **verbatim** essay/free-text answers), `notes`, and `record_basis` (`"live_capture"` for new ones).
- **`submission.md`** — same content rendered readable, with full essay text, for interview prep.

Rules:
- Capture **every** field actually submitted: each radio/dropdown selection, salary figure, source attribution, and the full verbatim text of every essay/free-text box.
- Write the record immediately after clicking submit (or filling, if submit is blocked), before moving to the next application.
- Keep `documents/applications/INDEX.md` updated (one row per application).
- The 22 applications from 2026-06-22..24 were backfilled after the fact (`record_basis: "backfilled_from_session_context"`); free-text in those is a high-fidelity reconstruction, not verbatim. All future records must be true live capture.

### Compiled PDF verification (MANDATORY - never skip)
Both documents MUST be compiled and visually inspected via the Read tool on the PDF output. "Looks fine in the .tex" is not acceptable - LaTeX page-break decisions are unpredictable. Iterate until these all pass:
- [ ] Compiled with the engine that matches the template. **Default (single-column `ajcv.cls` CV + `cover_aj.cls` letter): both with lualatex.** Alternative (moderncv CV + `cover.cls` letter): CV with lualatex, letter with xelatex. pdflatex is never used (modern fontspec/fontawesome5 installs fail on it). Binaries live at `/Library/TeX/texbin`; prefix commands with `export PATH="/Library/TeX/texbin:$PATH"` if not on PATH.
- [ ] **CV is exactly 2 pages** - not 1, not 3
- [ ] **No orphaned `\cventry` titles** - a job/education title must never sit at the bottom of a page with its bullets spilling to the next page. Use `\needspace{5\baselineskip}` before each `\cventry` to prevent this, and `\enlargethispage{2-3\baselineskip}` to rescue a trailing section that just barely spills
- [ ] **Cover letter is exactly 1 page** - signature block must fit with the body, never overflow
- [ ] **Cover letter bullet font matches body font.** In `cover_aj.cls` (default), use the `coverbullets` environment between `\lettercontent{}` blocks — it sets its own font, no hack needed, and `\closing{}` takes no trailing `\\`. In `cover.cls` (alternative), `\lettercontent{}` must not wrap `\begin{itemize}...\end{itemize}` (the trailing `\\` errors on `\end{itemize}`, and moving itemize outside loses the Raleway font); close `\lettercontent{}` first, then wrap the list in `{\raggedright\fontspec[Path = OpenFonts/fonts/raleway/]{Raleway-Medium}\fontsize{11pt}{13pt}\selectfont \begin{itemize}...\end{itemize}\par}`
