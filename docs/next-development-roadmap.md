## 1. 当前基线

### 已完成的代码能力

- 统一职位字段、中文薪资/日期/经验/学历/地点标准化和跨平台去重。
- 智联招聘只读搜索和详情适配器。
- 猎聘官方 CLI 只读包装、错误分类和 Token 脱敏。
- BOSS/51job 人工职位导入、原文归档、失败恢复和 `/rank` 本地归档路由。
- `/scrape`、`/rank` 的来源、标准化字段和安全边界接线。
- 本地 Web 控制台、简历文本识别、职位导入、排名只读看板和 OpenAI 兼容 AI 匹配入口。

### 等待统一验证

| 编号 | 验证项 | 前置条件 | 完成标准 |
|---|---|---|---|
| V1 | 智联 `/scrape → /rank` | 候选人配置完成 | 真实职位进入 `seen_jobs.json` 并完成排名状态写回 |
| V2 | 猎聘在线只读搜索 | 用户完成官方授权 | 低频搜索字段与适配器一致，`/scrape health` 状态正确 |
| V3 | BOSS/51job 人工导入 | 一条真实 URL 和复制正文 | 导入、归档、`/rank` 评分全流程成功 |
| V4 | OpenAI 兼容 AI 匹配 | 用户配置兼容服务 | 脱敏样本在明确确认后成功返回合法 JSON，错误和超时可解释 |

### 当前阻塞

- `CLAUDE.md` 和候选人画像仍有 `[YOUR_*]` 占位符，V1 暂不能做真实候选人排名。
- 猎聘 V2 需要用户自行完成授权；开发阶段不代填 Token。
- V1/V3/V4 的真实验收需要用户提供候选人资料、职位样本或 API 配置；代码测试不能替代在线验证。

## 2. 执行原则

1. 先保持现有 CLI 和 Markdown workflow 可独立运行，再增加 UI。
2. 验证任务与 UI 开发并行，不把猎聘授权或候选人资料阻塞整个产品化工作。
3. UI 只做编排、展示和输入简化，不复制门户解析和评分规则。
4. 每个阶段必须有离线测试、契约测试和可回滚的状态文件变更。
5. 所有外部平台访问继续低频、只读、可追溯；不绕过登录、验证码或风控。

## 3. 分阶段路线

### 阶段 A：现有能力验收收口

**目标：** 关闭 M2、M3、M4 的可验证缺口。  
**优先级：** P0。  
**可与阶段 B 并行：** 是。

| 顺序 | 工作项 | 交付物 | 结果 |
|---|---|---|---|
| A1 | 初始化候选人配置 | 真实候选人画像和搜索偏好 | 解除 T3.5 阻塞 |
| A2 | 智联真实端到端 | `/scrape → /rank` 验证记录 | M2 验收 |
| A3 | 人工导入真实样本 | BOSS/51job 导入记录和原文归档 | M4 验收 |
| A4 | 猎聘授权后低频搜索 | 字段核对和 health 记录 | M3/T4.8 验收 |

**阶段门禁：** A2-A4 只记录真实结果，不得为了通过验收伪造候选人资料、职位正文或 Token。

### 阶段 B：本地 Web MVP

**目标：** 小白不打开终端即可完成首次设置、搜索、导入和查看排名。  
**预计：** 3-5 个工作日。  
**对应任务：** T7.1-T7.9。

建议实现顺序：

1. **T7.1 信息架构**：首页、首次设置、搜索、导入、排名、平台状态和错误恢复页面。
2. **T7.2 一键启动/环境检查**：本地服务绑定 `127.0.0.1`，自动检查 Python、Bun 和已登记 CLI。
3. **T7.3 首次设置向导**：最多 5 个必填项，支持草稿保存和跳过。
4. **T7.6 搜索/排名看板**：先接入只读搜索、任务状态和排名展示。
5. **T7.7 职位导入页**：粘贴 URL，必要时粘贴正文，调用 `tools/import_job.py`。
6. **T7.8 安全与日志脱敏**：阻止 Token 进入 URL、页面日志和普通错误提示。
7. **T7.9 新手验收**：至少 5 名非技术用户完成核心流程。

T7.4（一句话目标解析）和 T7.5（简历导入）已完成首版代码，简历解析已补充中文技能、工作年限和语言能力；canonical profile 安全映射仍待开发。T7.6/T7.7 已完成基础只读/人工导入闭环，Web 搜索和 canonical `/rank` 任务编排已完成首版，等待真实平台和 AI 配置验收。

**阶段门禁：** UI 出现异常时，用户可以退回 CLI；UI 不得直接执行投递、私聊、简历修改或授权 Token 读取。

### 阶段 C：输入简化增强

**目标：** 减少重复录入，提高信息质量。  
**预计：** 3-7 个工作日。  
**对应任务：** T7.4、T7.5 的完整能力和增强项。

- 一句话目标解析：结果先确认，无法确定的字段进入“待确认”，不自动变成硬约束。
- PDF/Word/文本简历提取：展示来源片段和待确认标记，确认后才写入候选人配置。
- 职位、技能、城市模板：模板只提供建议，不覆盖用户已确认的配置。
- 渐进式补充：搜索前只问搜索必需信息，申请前再问材料相关信息。
- 输入恢复：解析失败保留原始句子、原文和上一次确认结果。

**阶段门禁：** 自动提取可以减少输入，但不能增加候选人的事实、技能、语言等级或工作经历。

### 阶段 D：浏览器辅助

**目标：** 降低 BOSS/51job 复制正文的操作成本。  
**状态：** 后续独立版本。  
**对应任务：** T6.1-T6.3。

1. 设计当前页面读取边界。
2. 读取用户明确选择的当前页面内容。
3. 检测登录页、验证页和 CAPTCHA，遇到这些状态立即中止。
4. 复用人工导入和原文归档，不自动提交表单或发送消息。

### 阶段 E：扩展来源和分发

**目标：** 扩大职位覆盖并降低安装成本。  
**状态：** P2/P3。

- 调查企业官网、Greenhouse、Lever、Workday 和国内企业 ATS。
- 每个新来源先做 robots、字段、详情和低频烟囱验证，再生成技能目录。
- 制作 Windows 安装包和自动更新提示。
- 可选浏览器扩展和系统通知。
- 云同步不进入默认版本，另行设计授权、加密和数据删除策略。

## 6. 统一验收门槛

- 新手不打开终端即可完成 P0 核心流程。
- 首次必填项不超过 5 项。
- 搜索、导入、排名失败时，页面给出明确的下一步动作。
- 原始输入和职位正文可恢复，状态文件不会被静默覆盖。
- Token、Cookie、密码、验证码和简历正文不出现在日志或 URL。
- 现有 CLI、`.claude/` 规范、`seen_jobs.json` 和申请跟踪兼容。
- 所有平台功能都有离线测试；在线功能另有低频验证记录。
- 任何外部副作用动作继续保留人工确认。

## 7. 当前执行结论

本轮不继续扩展更多招聘平台，也不先做自动投递。P1 的代码能力已覆盖搜索、排名、筛选、资料映射、简历格式、输入产品化、AI 治理和审计备份；剩余工作主要是 [P1 功能验收清单](./p1-acceptance-checklist.md) 中的真实平台/API 和五名非技术用户验收。
